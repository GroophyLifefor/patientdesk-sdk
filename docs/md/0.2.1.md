# Upgrading to 0.2.1

This guide covers `patientdesk-sdk` `0.2.0` to `0.2.1`. The release has no
breaking API or type change. It tracks a change in PatientDesk's voice catalog.

## At a glance

- Alania-2 now ships 11 built-in voices. The nine named voices also accept
  their bare name (`"nisa"`, `"öncel"` or `"oncel"`).
- `alania2-m2` and `alania2-f2` were retired on 12 October 2026. Requests
  naming them now get `400 unknown_voice`.
- The `AlaniaVoice` type lists the current built-ins. Any string is still
  accepted, so existing code keeps compiling.
- The SDK defaults are unchanged: `alania-v1` + `alania`, or `alania2-f1` when
  you pass `model: "alania-v2"` without a voice.

## The new voice set

| Voice | Note |
| --- | --- |
| `alania2-f1` | Female, Alania-2's default voice. |
| `alania2-nisa` | Female, gentle and playful. |
| `alania2-oncel` | Male, mature and reassuring. The default male voice. |
| `alania2-m1` | Male. |
| `alania2-emre` | Male, smooth and thoughtful. |
| `alania2-fikri` | Male, clear and gentle. |
| `alania2-sezgin` | Male, soft-spoken and breathy. |
| `alania2-selin` | Female, relaxed and friendly. |
| `alania2-lina` | Female, warm and calm. |
| `alania2-melisa` | Female, bright and energetic. |
| `alania2-nil` | Female, warm and enthusiastic. |

The named voices are designed voices (no actor recordings), each speaking from
its own fixed reference. They are not trained into the model, so with a style
or an `instructions` they drift a little further from their own timbre than
`alania2-f1` and `alania2-m1` do. See
[Text to speech](text-to-speech.md) for the full set including `alania` and
`antalia-mini`.

## What to change

Replace a retired voice with `alania2-f1`, `alania2-oncel` or another built-in:

```ts
// Before (now 400 unknown_voice)
await pd.speech.create({ model: "alania-v2", voice: "alania2-m2", input: "Merhaba" });

// After
await pd.speech.create({ model: "alania-v2", voice: "alania2-oncel", input: "Merhaba" });
```

A voice name works in the same field:

```ts
await pd.speech.create({ model: "alania-v2", voice: "nisa", input: "Merhaba" });
```

## Backward compatibility

- `voice` accepts any string, so code that names a retired voice still compiles
  and sends the request as-is. The API answers `400 unknown_voice` right away.
  The SDK does not retry `4xx` responses.
- The SDK does not validate voice ids locally, so saved voices, clones and
  designs are unaffected.
- The default paths (`alania` for `alania-v1`, `alania2-f1` for `alania-v2`)
  are untouched.

## Verifying the upgrade

```sh
npm run typecheck
npm test
```
